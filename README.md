# Books Scraper

A Scrapy project that crawls [books.toscrape.com](https://books.toscrape.com/), discovers all book categories dynamically, randomly samples categories and books, cleans the data in item pipelines, and stores it in SQLite and in JSON, CSV and XML files. It is packaged for Scrapyd and Docker.

## Project Overview

The spider starts at the homepage and:

1. Discovers all categories from the sidebar (nothing is hardcoded).
2. Randomly selects 5 to 10 categories.
3. Collects every book URL in each selected category, across all pages.
4. Randomly selects 5 books per category and extracts their data.
5. Cleans each item, stores it in SQLite, and exports it to JSON, CSV and XML.

| Field | Description |
|---|---|
| `title` | Book title |
| `price` | Price as a number, without currency symbol |
| `availability` | `True` if in stock, otherwise `False` |
| `product_url` | Product details page URL |
| `image_url` | Absolute cover image URL |
| `category` | Category name |

## Features

- Dynamic category discovery and random sampling of categories and books
- Pagination handled before sampling, so the sample covers the whole category
- Cleaning pipeline: whitespace, text normalization, price to float, availability to boolean
- SQLite storage through an item pipeline
- JSON, CSV and XML feed exports configured in `settings.py`
- Logging for crawling, processing and errors
- Scrapyd configuration and a self-deploying Docker image

## Tech Stack

Python 3.12, Scrapy (2.14 or newer), Scrapyd, scrapyd-client, SQLite, Docker.

## Environment Setup

| Variable | Default | Purpose |
|---|---|---|
| `OUTPUT_DIR` | `./output` | Folder for the exported files and `books.db` |

Sampling settings in `books_scraper/settings.py`:

| Setting | Default | Meaning |
|---|---|---|
| `CATEGORY_SAMPLE_MIN` | `5` | Minimum categories to pick |
| `CATEGORY_SAMPLE_MAX` | `10` | Maximum categories to pick |
| `BOOKS_PER_CATEGORY` | `5` | Books per selected category |

Any setting can be overridden with `-s NAME=value`.

## Running the Spider

```bash
scrapy crawl books
```

To cover every category:

```bash
scrapy crawl books -s CATEGORY_SAMPLE_MIN=50 -s CATEGORY_SAMPLE_MAX=50
```

Each run overwrites the previous files and clears the database table, so the files and the database always hold the same run.

## Docker Setup Guide

The image uses `python:3.12-slim`. On start, `entrypoint.sh` launches Scrapyd, waits for its API, and deploys the project automatically.

```bash
docker build -t books-scraper .
docker run --rm -p 6800:6800 -v "$(pwd)/output:/app/output" books-scraper
```

In a second terminal:

```bash
curl http://localhost:6800/schedule.json -d project=books_scraper -d spider=books
curl "http://localhost:6800/listjobs.json?project=books_scraper"
ls output/
```

Notes:

- Port 6800 must be free on the host, so stop any local Scrapyd first.
- If the container fails with `bad interpreter`, fix the line endings: `sed -i 's/\r$//' entrypoint.sh`, then rebuild.

## Scrapyd Deployment Guide

Relevant files: `scrapy.cfg` (deploy target), `scrapyd.conf` (server config), `setup.py` (generated by `scrapyd-deploy`).

Terminal 1, start Scrapyd from the project root:

```bash
export OUTPUT_DIR="$(pwd)/output"
scrapyd
```

Terminal 2, deploy and run:

```bash
scrapyd-deploy
curl "http://localhost:6800/listspiders.json?project=books_scraper"
curl http://localhost:6800/schedule.json -d project=books_scraper -d spider=books
curl "http://localhost:6800/listjobs.json?project=books_scraper"
```

`scrapyd-deploy` should return `"status": "ok"` and `listspiders.json` should list `books`. Job logs are in `logs/books_scraper/books/<jobid>.log`, and the web interface is at `http://localhost:6800`.

| Problem | Fix |
|---|---|
| `Unknown target: default` | Uncomment the `url` line in `[deploy]` in `scrapy.cfg` |
| `ModuleNotFoundError: pkg_resources` | `pip install "setuptools<81"` |
| Job finishes but `output/` is empty | Export `OUTPUT_DIR` before starting `scrapyd` |

## Output Format Description

Files are written to `OUTPUT_DIR` with a fixed field order.

| Field | JSON | CSV / XML | SQLite |
|---|---|---|---|
| `price` | number (`51.77`) | `51.77` | `REAL` |
| `availability` | `true` / `false` | `True` / `False` | `INTEGER` (`1` / `0`) |
| other fields | string | text | `TEXT` |

- `books.json`: a list of objects.
- `books.csv`: header `title,price,availability,product_url,image_url,category`.
- `books.xml`: root `<books>`, one `<book>` per item with one child element per field.

Example JSON record:

```json
{
  "title": "A Light in the Attic",
  "price": 51.77,
  "availability": true,
  "product_url": "https://books.toscrape.com/catalogue/a-light-in-the-attic_1000/index.html",
  "image_url": "https://books.toscrape.com/media/cache/fe/72/fe72f0532301ec28892ae79a629a293c.jpg",
  "category": "Poetry"
}
```

## Database Configuration

SQLite, stored at `OUTPUT_DIR/books.db` (setting `SQLITE_DB_PATH`). No server or credentials are needed.

```sql
CREATE TABLE IF NOT EXISTS books (
    product_url  TEXT PRIMARY KEY,
    title        TEXT NOT NULL,
    price        REAL NOT NULL,
    availability INTEGER NOT NULL,
    image_url    TEXT,
    category     TEXT
);
```

- `SQLitePipeline` creates the table, clears old rows when the spider starts, inserts with `INSERT OR REPLACE`, and commits when the spider closes.
- If an insert fails, the item is dropped and logged, so it is also kept out of the exported files.

```bash
sqlite3 output/books.db "SELECT category, COUNT(*) FROM books GROUP BY category;"
```

## Design Decisions

- **Category sampling:** the spider discovers all categories, randomly picks 5 to 10 of them, then picks 5 books in each. Setting both limits to 50 covers every category.
- **Sampling after pagination:** book URLs from all pages are collected first and sampled once, so the sample is random over the whole category. Categories with fewer than 5 books yield all their books.
- **Spider only crawls:** it yields raw values. Cleaning and validation happen in `CleaningPipeline`, using pure helper functions in `utils.py`.
- **Same data everywhere:** pipelines run before feed exports, so files and database receive the same cleaned items. The database is cleared and the files overwritten on every run.
- **Configuration over code:** sampling sizes, feeds and paths live in `settings.py`, and the output folder comes from `OUTPUT_DIR`, so the code runs unchanged locally, under Scrapyd and in Docker.
- **Kept simple:** one spider, two pipelines, one utils module, no extra abstraction layers.
